# Live answer track and judge check — November 12, 2026

The answer track ran against the live model for the first time, and the judge was
then tested on answers with defects planted on purpose. This report covers what was
run, what it found, and what it does not establish. It is **not** a calibration
against human judgment: no human labels were collected.

## What ran

| Step | Scope | Result | Cost |
|---|---|---|---:|
| Live run 1 | 30 English smoke cases, hybrid, k=3, generator prompt v1 | 30/30 scored, 0 failed | $0.5248 |
| Live run 2 | Same, generator prompt v2 | 30/30 scored, 0 failed | $0.5006 |
| Judge check | 30 answers from run 2 + 12 planted defects | 42/42 judged | $0.4426 |

Model `claude-opus-4-8` generated and judged; judge prompt `structured-scores-v1`.
Retrieval in both runs matched the retained hybrid baseline exactly. Total estimated
spend was **$1.47** at standard token rates. Median usage per case was about 800
input / 85 output tokens for generation and 1,430 / 120 for judging, with median
stage latencies near 1.9 s and 2.5 s.

## Finding 1: the generator invented passage ids

In run 1, **4 of 30 answers cited ids that were never retrieved**: `[doc:0]`,
`[doc:embeddings:0]` and similar. The system prompt showed `[doc:0]` as a sample
id, and the model copied the sample or its `doc:` prefix. The judge scored the
citations of all four answers **1.0**.

Two changes followed:

- The prompt now describes the citation format without a concrete sample
  (`grounded-citations-v2`). Run 2 produced **0 of 30** such answers.
- Cited ids that match no retrieved passage are detected in code, stored per case
  and shown in the CLI summary and the case view. The check does not depend on
  the judge.

## Finding 2: full marks on every real answer

Both runs scored 1.000 on faithfulness, relevance and citation correctness for all
30 cases. Judging the 30 answers of run 2 a second time returned the same score on
90 of 90 dimensions. The smoke questions are short and extractive, so this is a
ceiling, and by itself it cannot show that the judge separates good answers from
bad ones. The next section tests that directly.

## Planted-defect check

Twelve answers were derived from run 2, three per defect, each built to lower one
dimension while leaving the others intact. A defect counts as detected when the
judge's score on the target dimension falls below 0.75.

| Planted defect | Target | Judge scores | Detected |
|---|---|---|---:|
| An added claim absent from every passage | Faithfulness | 0.4, 0.5, 0.4 | 3 / 3 |
| A grounded, correctly cited answer to a different question | Relevance | 0.3, 0.1, 0.0 | 3 / 3 |
| Citation moved to a retrieved passage about something else | Citations | 0.0, 0.0, 0.0 | 3 / 3 |
| Citation rewritten to an id that matches no passage | Citations | 0.5, 0.0, **1.0** | 2 / 3 |
| **Total** | | | **11 / 12** |

- **No false alarms.** None of the 30 untouched answers scored below 1.0 on any
  dimension.
- **No collateral damage.** Every defect lowered only its target dimension; the
  other two stayed at 1.0 in all twelve items.
- **One added claim was true but ungrounded** (BM25's origin and default
  parameters). The judge scored it 0.4 on faithfulness, treating a correct fact
  that the passages do not contain as unsupported.
- **The miss is the failure from finding 1.** `[doc:evaluation-metrics:0]` was
  accepted as if it were `evaluation-metrics:0`. Across the three non-existent
  ids the judge returned 0.0, 0.5 and 1.0, so it is inconsistent on exactly the
  error the code check now catches every time.

## What this does not establish

- **No human review.** Agreement between the judge and a person was not measured.
  The tooling is in place: `rag calibrate-judge --labels` merges human labels at
  three levels per dimension and reports level agreement and its direction.
- **The defects are blatant and assistant-authored.** They were constructed for
  this check, one clear defect per answer, not sampled from real failures. Subtle
  errors, partial answers and mixed defects were not tested.
- **Small and narrow.** Three items per defect, one English corpus of ten
  documents, one model acting as both generator and judge, and a single judge
  trial per planted item.
- **Not answer quality.** Full marks on easy extractive questions say little about
  harder or unanswerable ones. The rubric has no completeness, correctness against
  the reference or abstention dimension.

## Reproduce

```bash
uv run rag ingest
RAG_ANTHROPIC_API_KEY=... uv run rag eval --judge --strategy hybrid --k 3

# Re-judge the retained set (42 paid calls), then print the planted-defect report.
RAG_ANTHROPIC_API_KEY=... uv run rag calibrate-judge \
  --set benchmarks/judge-calibration/2026-11-12.json --score
uv run rag calibrate-judge --set benchmarks/judge-calibration/2026-11-12.json
```

The [calibration set](../benchmarks/judge-calibration/2026-11-12.json) holds every
item with its question, retrieved passages, answer, the edit that produced each
defect and the judge's scores and rationale. Compact numbers are in
[judge-2026-11-12-results.json](judge-2026-11-12-results.json). Model output varies
between calls, so a repeat run can differ from the scores recorded here.
